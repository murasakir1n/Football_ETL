# Демонстрационные данные

Каталог содержит сохранённые JSON-ответы API [football-data.org](https://www.football-data.org/). Они подходят для изучения структуры входных данных и локальной отладки преобразований без обращения к API (и без расхода лимита бесплатного тарифа).

Это те же ответы, что Airflow на сервере складывает в слой raw объектного хранилища (`raw/teams/`, `raw/matches/`), только в виде небольшой выборки для репозитория.

## Состав

| Путь | Содержимое |
| --- | --- |
| `teams/` | Списки команд, составы игроков и метаданные турниров. Один файл на лигу. |
| `matches/` | Матчи и метаданные соответствующих турниров. Один файл на лигу. |
| `wc_countries.json` | Справочник стран и регионов (иерархия через `parentAreaId`: страна → континент → мир). |

В каталогах `teams/` и `matches/` представлены данные для Бундеслиги (`bl1`), Бразилейрао (`bsa`), Эредивизи (`ded`), Лиги 1 (`fl1`), Примеры (`pd`), Премьер-лиги (`pl`), Примейры (`ppl`) и Серии A (`sa`).

## Как это использовать

Файлы являются исходными ответами API, а не данными в схеме PostgreSQL. При загрузке DAG-и выбирают из них нужные поля и записывают нормализованные сущности в таблицы `competitions`, `teams`, `players` и `matches` (см. [`../sql/`](../sql/README.md)).

Быстро посмотреть структуру ответа:

```bash
python -m json.tool sample_data/teams/pl.json | less
# или, если установлен jq:
jq 'keys' sample_data/matches/pl.json
```

Эти файлы удобны, чтобы:

- понять, какие поля отдаёт API, прежде чем писать преобразование;
- отлаживать трансформации в DAG-ах локально, подставляя файл вместо запроса к API;
- воспроизвести граничные случаи, например игрока, числящегося в двух командах.

> Примеры не обновляются автоматически и могут отставать от актуального состояния лиг.
